How it is counted

A command counts as implemented when the runtime has its own arm for it in the match of the service (crates/rt/src/services/**/*.rs), the SVC (horizon.rs) or the device ioctl (services/nvdrv.rs and services/nvdrv/*.rs); anything that falls to the default arm goes to the stub, which answers with zeros and warns. A service split into a folder counts like a single file: the scanner follows the inherent impl and the free function a call delegates to across the module. A struct the registry constructs under several names (bsd:u, bsd:s, bsd:a) is one dispatch, so each name is counted against its own reference table with the same arms. The Constant column sets apart implemented commands whose body only returns success or fixed values. Ioctls are compared by the low byte of their number, which is how the devices dispatch them.

The totals are the commands documented on Switchbrew (tools/reference/horizon.txt, IDs and names only) for the interfaces Kirikae exposes or games ask for, not every system service. A new interface joins the count when it joins the reference.

Shader instructions count the mnemonics of the Maxwell opcode table generated from envytools (crates/maxwell/src/opcodes.rs) that have their own arm in the SPIR-V translator (crates/maxwell/src/translate.rs). A mnemonic counts whole even when only some of its variants are translated.
